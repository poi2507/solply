# 수익모델 — 3층 구조 (2026-07-28 확정)

> 소개서 필수 4요소 중 하나. 한 줄 버전:
> **"구독으로 시작해, 지점 간 거래가 늘면 중개료가 자라고, 쌓인 온체인 신용이 여신 시장을 연다."**

## 구조

| 층 | 모델 | 누가 내나 | 무엇에 대한 대가 | 가격 예시 |
|---|---|---|---|---|
| **1층 · 지금 돈** | SaaS 구독 | 본사 | 정산 자동화 — 경리 인건비 절감, 검수 분쟁 처리, 미수금 실시간 가시성 | 지점당 월 29,000원 |
| **2층 · 성장** | P2P 직거래 중개료 | 거래 지점 | 재고 매칭 + 본사 품질 승인 + 온체인 증빙 | 거래액의 1% |
| **3층 · 비전** | 온체인 신용 여신 | 금융사 | 조작 불가능한 납부 이력 기반 스코어링 API·대출 중개 | API 사용료 / 실행액의 bp |

## 층별 논리

### 1층 — SaaS 구독: 심사위원이 익숙한 셈법

고객은 가맹점이 아니라 **본사**다. 지점 100개 브랜드면 월 290만 원 — 정산 담당자
한 명 인건비의 절반이 안 되는 돈으로 청구·검수 분쟁·수금 관리가 사람 없이 돈다.
B2B SaaS라 설명 비용이 없고, 도입 단위(브랜드)가 명확하다.

### 2층 — P2P 중개료: 우리가 만든 거래에서 나오는 돈

지점 간 잉여 재고 직거래(시나리오 E)는 Solply가 없으면 존재하지 않던 거래다.
여기서 받는 1%는 **결제 수수료가 아니라 서비스료** — 잉여·부족 매칭, 본사의
위생·품질 승인, 온체인 인수 증빙에 대한 대가다. 파는 쪽은 폐기될 재고가
현금이 되므로 1%를 아까워할 이유가 없다.

### 3층 — 여신: "점주가 자기 온체인 신용을 들고 다닌다"

신용 이력을 금융사에 *판매*하는 모델이 아니다 — 프라이버시 반론에 취약하다.
반대로 **점주의 동의 하에, 조작 불가능한 납부 이력을 점주 자신의 자산으로**
금융사에 제시해 운전자금 대출 조건을 개선하고, Solply는 스코어링 API 사용료와
중개 수수료를 받는다. 데모와 직결되는 층이다: 심사위원은 정산이 완료되는 순간
신용점수가 88→90으로 오르는 것을 화면에서 직접 본다.

## 시장 크기 셈법 (소개서용)

국내 프랜차이즈 가맹점 약 35만 개(공정거래위원회 가맹사업 통계 기준 — **제출 전
최신 수치 재확인**). 1%인 3,500개 지점만 확보해도:

- 1층: 3,500 × 29,000원 = **월 약 1억 원** 구독 매출
- 2층: 지점당 월 직거래 20만 원 가정 시 × 1% = 월 700만 원 (거래량에 비례해 성장)
- 3층: 지점당 평균 운전자금 대출 1,000만 원 × 중개 50bp = 건당 5만 원 + API 매출

## Q&A 방어 3문답

**"왜 건당 정산 수수료를 안 받나?"** — 우리 논거가 "온체인 정산은 싸다"이기
때문이다. 정산 건당 과금은 그 논거와 충돌한다. 돈은 정산이 아니라 자동화(구독)·
매칭(중개)·신용(여신)에서 받는다.

**"P2P 1%는 결제 수수료 아닌가?"** — 아니다. 결제는 지점 간 온체인 직접 전송이라
우리를 거치지 않는다. 1%는 매칭·승인·증빙이라는 서비스에 대한 대가고, 이
거래 자체가 우리 플랫폼이 만들어낸 신규 거래다.

**"신용 데이터 팔면 프라이버시 문제 아닌가?"** — 팔지 않는다. 데이터의 주인은
점주고, 점주가 동의할 때만 자기 이력을 제시한다. 온체인이라 금융사는 위조를
의심할 필요가 없고, 점주는 성실 납부가 곧 대출 조건이 되는 자산을 얻는다.
