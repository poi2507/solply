x402 — 402 응답이 곧 협상 테이블

Ⅱ 기술 · x402 프로토콜

HTTP에는 402 Payment Required가 30년 넘게 비어 있었습니다. x402는 그 빈 칸을 채운 규약이고, 우리는 판매자와 구매자 양쪽을 직접 구현했습니다.

  { "term": "immediate", "amount": "6500000",
    "memo": "INV-0729-B01" },
  { "term": "deferred", "requiresApproval": true,
    "policyHint": "외상 한도의 20% 이내면 자동 수락" },
  { "term": "installment", "installments": 2,
    "amount": "3250000" } ] }

이 배열이 곧 메뉴판입니다

accepts의 세 항목이 세 가지 결제 조건입니다. 지점 에이전트는 잔액과 정책 상한을 보고 하나를 고르거나, 어느 것도 맞지 않으면 역제안합니다. policyHint는 본사 정책에서 그때그때 채워집니다 — 숫자가 코드에 박혀 있지 않습니다.

기존 물대: 외상 30–60일

표준 안에서 협상

x402의 accepts는 배열입니다. 원래는 결제 수단 선택용이지만, 여기에 결제 조건을 담아 규약을 벗어나지 않고 협상을 표현했습니다.

서명만 확인하면 다른 청구서의 결제를 재사용할 수 있습니다. 금액·메모·성공을 함께 봐야 그 구멍이 막힙니다.

지점 에이전트는 청구서를 받으면 네 개의 관문을 순서대로 지납니다. 막히는 자리마다 대응이 다릅니다 — 그래서 결과가 네 가지로 갈립니다.

4
내가 정할 금액인가

자동결제 한도를 넘으면 사람에게 넘깁니다.

① 검수 불일치

수량이 다르면 차액을 빼달라고 제안. 본사가 검수 기록으로 재검증하고 청구서를 재발행한다.

② 잔액 부족

예상 입금 일정을 근거로 유예를 요청. 신용점수가 기준을 넘으면 본사가 납부일을 잡아준다.

③ 전액 유예 불가
