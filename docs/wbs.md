무엇을 더 만들지 정하기 전에, 심사 기준별로 지금 무엇이 비어 있는지 봤다.

| 심사 기준 | 현재 | 갭 |
|---|---|---|
| 혁신성·UX | 대시보드 있음 | 협상 과정이 잘 드러나는가 |

| 인프라 연동 | USDC 결제 ✅ / x402 엔드포인트만 | **에이전트가 x402를 안 쓴다**, pay.sh 미사용 |
| 실제 구동 | 로컬넷 ✅ | **devnet 미전환** → explorer 링크가 없다 |

이 표에서 나온 우선순위:

### 채택 — 반드시 한다
1. **x402를 에이전트 플로우에 연결** — 지금 엔드포인트와 에이전트가 따로 논다. 심사 기준 3의 핵심인데 "만들어는 뒀다" 수준이면 점수가 안 된다.
2. **온체인 신용점수 실계산** — 지금 88/81/92가 `fixtures.json`에 박혀 있다. 이걸 **실제 결제 이력에서 계산**하면 "납부 이력이 곧 신용"이라는 우리 논거가 데모로 증명된다. 발표에서 가장 강한 한 방이 될 수 있다.
3. **이상 청구 거부 시나리오** — `refuse_payment` 도구는 이미 있고 데모에만 없다. 싸고 임팩트 크다. "에이전트가 돈을 아무 데나 쓰지 않는다"를 증명한다.
4. **예약 납부 실행** — C지점이 `scheduled`에서 멈춰 있어 시나리오가 미완이다.
5. **devnet 전환 + Cloud Run 배포** — explorer 링크와 라이브 URL 없이는 심사에서 불리하다.

6. **가맹점 간 직거래 (시나리오 E)** — (7/27 사용자 아이디어) A지점 잉여 재고를 B지점이 에이전트 간 협상으로 인수, B→A 온체인 결제 + 본사 승인. **채택 → Phase 2.5로 정식 편성.** 근거: 기존 시나리오가 트랙 A·B만 커버하는데 이게 **트랙 C(Multi-Agent Commerce)를 정면으로 채운다**. 결제 레일을 전부 재사용하므로 구현이 싸고, 본사 승인 단계가 "자율성+통제" 서사를 P2P로 확장한다. 설계는 [store-to-store-design.md](store-to-store-design.md)에 완료.

### 파이널 주간 백로그 (8/10–20 멘토링, 파이널 진출 시)

**1순위 — A2A 전환 (멀티테넌트의 뼈대).** 지금은 본사·지점 에이전트 4대가
Solply 백엔드 한 프로세스 안에서 돌고 오케스트레이터(demo.py)가 왕복을 중개한다.
이를 "주체가 각자 소유하는" 구조로 옮긴다. **키 분리는 이 전환의 결과물이지
독립 작업이 아니다** — 순서가 중요하다:

| 단계 | 작업 | 비고 |
|---|---|---|
| ① 프로세스 분리 | 지점 에이전트를 독립 서비스로 — 에이전트가 이미 독립 그래프라 떼어내면 된다 | x402는 애초에 HTTP 경계라 그대로 감 |
| ② A2A 메시징 | 오케스트레이터 자리를 A2A 프로토콜(에이전트 카드·상호 인증)로 교체 | 심사 기준 3의 "A2A x402 extension"과 정합. ADK의 A2A 노출 활용 검토 |
| ③ 자격증명 소유 분리 | 각 테넌트가 자기 LLM 자격증명(GCP 프로젝트)·지갑·정책을 소유 | 지갑·정책은 이미 주체별 분리 ✓ — LLM 자격증명만 남음. 지점이 다른 모델/제공자를 써도 A2A는 무관 |

**2순위 — 발주 자동화 (상거래 루프 완성).** 지금 납품은 시드 데이터(전제)다.
재고 이벤트 트리거 → 조달 계획(P2P vs 본사 발주 비교는 이미 있음) → 정책 경계 내
자율 발주(초과 시 기존 승인 게이트 재사용) → 본사 이행 → 납품·청구 생성으로
루프를 닫는다. **원칙: 발주 버튼(사람 트리거)을 만들지 않는다** — 결제와 같은
문법(사건 트리거 + 경계에서만 사람). 점주의 수동 발주는 어시스턴트 도구로.

**3순위 — 원래 미뤄둔 것들:** Pub/Sub·Eventarc·Workflows 파이프라인(납품 이벤트
트리거 — 오케스트레이터 호출부를 구독자로 교체하면 됨), BigQuery 정산 이력 적재,
Firestore 백엔드, 위 DB 백로그 1·2·4·5, pay.sh(Discord 답변 오면), 정책 영향 미리보기 UI.

## Phase 2.8 — 화면 재설계 ✅ 완료 (7/28 밤, 집 맥)

"한 화면에서 본사·가맹점을 다 하려니 가독성이 나쁘다"는 지적에서 시작해 두 단계로 고쳤다.

|---|---|---|
